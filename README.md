# ЧестныйРозыгрыш — розыгрыши «подарок за репост» во ВКонтакте и Instagram

Сервис проверяет выполнение условий розыгрыша, выбирает победителей проверяемым генератором
случайных чисел и формирует публичный отчёт по ссылке `/r/<id>`.

## Запуск

Нужен только Node.js 22.13+ (сторонних зависимостей нет, база данных — встроенный SQLite, файл `data/app.db`).

```bash
node server.js
```

Откройте http://localhost:3000. Без токенов работает **демо-режим** со сгенерированными участниками.

Токены задаёт администратор: на странице `/admin.html` → «Настройки» (там же кнопка «Проверить») или в файле `.env`
(скопируйте `.env.example`). Обычные пользователи ключи не вводят и не видят.

### ВКонтакте
1. Создайте приложение на https://dev.vk.com (тип «Standalone» или «Web»).
2. В настройках приложения скопируйте **сервисный ключ доступа** → `VK_TOKEN`.
   Для закрытых сообществ или если сервисного ключа не хватает — используйте ключ пользователя-администратора.
3. Используемые методы: `wall.getById`, `likes.getList` (лайки и репосты), `wall.getComments`,
   `users.get`, `groups.getById`, `groups.isMember`.

### Instagram

> **Сейчас скрыт.** Розыгрыши в Instagram отключены, пока не сделан вход клиентов через Instagram (OAuth):
> один серверный токен даёт доступ только к постам своего аккаунта. Код сохранён; чтобы включить обратно,
> добавьте `INSTAGRAM_ENABLED=1` в `.env` и перезапустите сервис. Старые отчёты Instagram открываются как раньше.

Официальный Instagram Graph API работает только с **профессиональным** (Business/Creator) аккаунтом,
привязанным к странице Facebook, и только с **его собственными** постами.
1. Создайте приложение в https://developers.facebook.com, добавьте продукт Instagram Graph API.
2. Получите долгосрочный токен с правами `instagram_basic`, `instagram_manage_comments`, `pages_show_list` → `IG_TOKEN`.
3. ID Instagram-аккаунта (`/me/accounts?fields=instagram_business_account`) → `IG_USER_ID`.

**Ограничение API:** Instagram отдаёт полный список комментариев, но **не отдаёт списки лайкнувших и подписчиков**
(только количество). Поэтому условия «лайк» и «подписка» проверяются по спискам никнеймов, которые организатор
загружает в форму (.txt/.csv). В отчёте это явно указано. Фото победителей подтягиваются через
`business_discovery` — для личных аккаунтов API фото не отдаёт, показывается заглушка.

## Аккаунты, оплата и доступ

- **Демо-розыгрыши** доступны всем без регистрации.
- **Розыгрыши по реальным постам** — только для зарегистрированных пользователей с оплаченным периодом.
  Проверка выполняется на сервере (`/api/draw` вернёт 401/402), а не только в интерфейсе.
- Регистрация и вход по e-mail и паролю. Пароли хранятся как scrypt-хеш с солью, сессия — HttpOnly-cookie
  на 30 дней (в базе лежит только хеш токена). После 10 неудачных попыток входа — пауза 15 минут.
- Личный кабинет `/account.html`: срок доступа, тарифы, история оплат с оплаченными периодами, свои розыгрыши, смена пароля.
- История розыгрышей видна только владельцу; сами отчёты остаются публичными по ссылке.
- «Исключить победителей прошлых розыгрышей» учитывает только розыгрыши этого же пользователя.

### Восстановление пароля
На странице входа — ссылка «Забыли пароль?». Сервис отправляет письмо со ссылкой, которая действует 1 час и
срабатывает один раз. После смены пароля пользователь сразу входит, а все его прочие сессии и старые ссылки гаснут.
Ответ одинаков для существующих и несуществующих адресов (нельзя выяснить, кто зарегистрирован);
ограничения — 3 письма в час на адрес и 5 запросов в час с одного IP.

Почта отправляется по SMTP без сторонних библиотек. Пример для Яндекс 360 (нужен «пароль приложения»):
```
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USER=noreply@ваш-домен.ru
SMTP_PASS=пароль-приложения
SMTP_FROM=ЧестныйРозыгрыш <noreply@ваш-домен.ru>
```
Mail.ru: `smtp.mail.ru`, порт 465. Подойдут и сервисы рассылок (Unisender Go, SendPulse) — у них лучше доставляемость.
Чтобы письма не попадали в спам, настройте для домена записи SPF и DKIM (инструкция есть у почтового сервиса).
Пока SMTP не настроен, ссылка восстановления печатается в консоль сервера (в production без SMTP функция отключена).

### Тарифы и учёт периода
Тарифы задаются в `lib/billing.js` (массив `PLANS`): по умолчанию 1 день — 290 ₽, 30 дней — 990 ₽, 365 дней — 4990 ₽.
Срок доступа хранится в `users.paid_until`. Каждый успешный платёж продлевает его на срок тарифа: от текущей даты
окончания, если доступ ещё действует, или от момента оплаты, если истёк. Платёж засчитывается ровно один раз,
а в каждой записи об оплате сохраняется, какой именно период она оплатила.

### ЮKassa
1. Личный кабинет ЮKassa → Интеграция → Ключи API: `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`.
2. Интеграция → HTTP-уведомления: URL `https://ваш-сайт/api/yookassa/webhook`, событие `payment.succeeded` и `payment.canceled`.
3. `PUBLIC_URL=https://ваш-сайт` — сюда ЮKassa вернёт покупателя после оплаты.
4. Если подключены чеки (54-ФЗ): `YOOKASSA_RECEIPT=1` и `YOOKASSA_VAT_CODE` (1 — без НДС).

Данным из уведомления сервис не доверяет: он всегда перезапрашивает статус платежа у ЮKassa и сверяет сумму.
Кроме того, статус проверяется, когда покупатель возвращается в кабинет, — доступ продлится, даже если уведомление не дошло.

**Тестовая оплата.** Пока ключи ЮKassa не заданы и `NODE_ENV` не равен `production`, вместо ЮKassa открывается
страница-имитация (деньги не списываются). В production без ключей покупка просто недоступна.

### Администратор
Укажите свой e-mail в `ADMIN_EMAILS`, зарегистрируйтесь — появится страница `/admin.html`: пользователи, сроки,
суммы оплат, все платежи и ручное продление или сокращение срока (например, при оплате по счёту) с причиной.

## Механики

| Механика | Как работает |
|---|---|
| Случайный выбор | Генератор выбирает номер → проверка условий → при невыполнении перевыбор (или сначала отсев, потом выбор) |
| Комментарий = шанс | Каждый подходящий комментарий — отдельный билет; один приз в одни руки |
| По номеру комментария | 50-й, 100-й… комментарий; если автор не выполнил условия — следующий |
| Угадай число | Генератор загадывает число; побеждает ближайший ответ, при равенстве — более ранний |
| Первые N | Первые N участников, выполнивших условия |

Условия: подписка на одно или несколько сообществ (организатор + спонсоры), лайк, репост, комментарий,
ключевое слово, отметка N друзей, минимальная длина и количество комментариев, дедлайн, учёт ответов в ветках.
Фильтры (VK): удалённые/заблокированные, закрытые профили, без фото, пол, возраст, город.
Исключения: организатор, чёрный список, победители прошлых розыгрышей за N дней. Резервные победители.

## Как обеспечивается честность

1. Собираются данные, проверяется каждый участник, формируется упорядоченный список (по ID).
2. Считается SHA-256 списка и SHA-256 итогов проверки условий (`id|1` / `id|0` по каждому участнику) —
   после этого ни список, ни вердикты изменить незаметно нельзя.
3. Выбирается **будущий** раунд публичного маяка [drand](https://drand.love) (League of Entropy), значение которого
   в момент фиксации не знает никто.
4. `seed = SHA-256(randomness + ":" + хеш списка + ":" + хеш итогов)`, k-е число = `HMAC-SHA256(seed, "draw:k")` → 48 бит →
   равномерное число 1..N методом отбрасывания.
5. Отчёт содержит всё необходимое для повторения расчёта; кнопка «Проверить» на странице отчёта пересчитывает
   всё в браузере и сверяет раунд напрямую с drand.

6. Перезапуски видны: каждый отчёт показывает, сколько всего розыгрышей проводилось по этому посту (со ссылками
   на все, включая более поздние). Пост определяется по его ID в соцсети, а не по тексту ссылки, поэтому другая
   форма ссылки не помогает скрыть повтор. Список считается при открытии отчёта и не хранится в самом отчёте.

Если drand недоступен, используется `crypto.randomBytes` сервера — это явно указывается в отчёте.

## Публикация на сайте

Пошаговая инструкция — в [DEPLOY.md](DEPLOY.md): VPS, домен, HTTPS, автозапуск, обновления и резервные копии
(скрипты в папке `deploy/`), а также чек-лист перед запуском продаж (оферта, политика ПДн, Роскомнадзор, ЮKassa).

## Структура

```
server.js          HTTP-сервер и API (/api/draw, /api/jobs/:id, /api/reports, /r/:id)
lib/vk.js          сбор данных VK API
lib/instagram.js   сбор данных Instagram Graph API
lib/demo.js        демо-данные
lib/engine.js      проверка условий и механики
lib/rng.js         проверяемый ГСЧ (drand + HMAC)
lib/store.js       хранение отчётов (data/reports/*.json + таблица draws)
lib/db.js          база SQLite: пользователи, сессии, платежи, розыгрыши
lib/auth.js        регистрация, вход, сессии
lib/billing.js     тарифы, ЮKassa, учёт оплаченного периода
lib/mailer.js      отправка писем по SMTP
public/            интерфейс: главная, отчёт, вход, кабинет, админка, тестовая оплата
```

## Для публичного размещения

- Поставьте за reverse-proxy с HTTPS (nginx/Caddy), запускайте через pm2 или systemd.
  Задайте `NODE_ENV=production`, `COOKIE_SECURE=1`, `TRUST_PROXY=1`, `PUBLIC_URL`.
- Регулярно копируйте папку `data/` (база и отчёты) — это резервная копия всех пользователей и оплат.
- Перед приёмом платежей опубликуйте оферту, политику конфиденциальности и контакты — этого требуют ЮKassa и 152-ФЗ.
- Храните токены в `.env` на сервере, а не в браузере, если сервисом пользуются другие люди.
- Для очень больших постов (50 000+ участников) сбор VK идёт ~3 запроса/сек — это может занять несколько минут.
