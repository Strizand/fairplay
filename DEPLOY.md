# Публикация на сайте

Сервис хранит данные в файле SQLite и держит запущенные розыгрыши в памяти процесса, поэтому нужен
**VPS** (свой сервер с постоянным диском), а не «бессерверный» хостинг.

## Что понадобится

| Что | Где взять | Зачем |
|---|---|---|
| Домен, например `rozygrysh.ru` | reg.ru, nic.ru и др. | Адрес сайта; HTTPS нужен для оплаты и безопасного входа |
| VPS: Ubuntu 22.04 или 24.04, 1 ядро, 1–2 ГБ памяти | Timeweb Cloud, Selectel, REG.RU, Beget и др. | Здесь работает сервис |
| Сервер **в России** | — | 152-ФЗ: персональные данные граждан РФ хранятся в базах на территории РФ |

## Установка (≈15 минут)

1. **DNS.** В панели регистратора домена создайте записи `A` для `rozygrysh.ru` и `www.rozygrysh.ru` с IP-адресом сервера.
   Подождите, пока они начнут работать (обычно 5–30 минут; проверка: `ping rozygrysh.ru`).
2. **Скрипт установки.** Подключитесь к серверу по SSH и скопируйте на него `deploy/install.sh`
   (например, `scp deploy/install.sh root@IP:/root/`). Затем:
   ```bash
   sudo bash install.sh rozygrysh.ru ваш@email.ru
   ```
   Скрипт ставит Node.js 22, Caddy (HTTPS), SQLite, файрвол; создаёт пользователя `fairplay`; создаёт `.env`;
   запускает службу и настраивает ежедневную резервную копию.
3. **Ключ доступа к GitHub.** Посреди установки скрипт покажет ключ `ssh-ed25519 …`. Добавьте его в GitHub:
   репозиторий `Strizand/fairplay` → **Settings → Deploy keys → Add deploy key**, галочку *Allow write access*
   **не** ставьте. Вернитесь к серверу и нажмите Enter.
4. **Первый вход.** Откройте `https://rozygrysh.ru` и зарегистрируйтесь с адресом, указанным при установке, —
   это администратор.
5. **Настройки** — `https://rozygrysh.ru/admin.html` → «⚙ Настройки»:
   - **Реквизиты продавца** — подставятся в оферту, политику и контакты (без них ЮKassa не пропустит сайт);
   - **ВКонтакте** — сервисный ключ, кнопка «Проверить подключение»;
   - **Почта** — SMTP для писем восстановления пароля, кнопка «Отправить тестовое письмо себе»;
   - **Оплата — ЮKassa** — shopId и секретный ключ. В кабинете ЮKassa → Интеграция → HTTP-уведомления
     укажите `https://rozygrysh.ru/api/yookassa/webhook`, события `payment.succeeded` и `payment.canceled`.

## Повседневная работа

| Задача | Команда на сервере |
|---|---|
| Обновить до последней версии из GitHub | `sudo bash /home/fairplay/app/deploy/update.sh` |
| Статус / перезапуск | `sudo systemctl status fairplay` / `sudo systemctl restart fairplay` |
| Журнал сервиса | `sudo journalctl -u fairplay -f` |
| Сделать копию вручную | `sudo bash /home/fairplay/app/deploy/backup.sh` |
| Изменить `.env` | `sudo -u fairplay nano /home/fairplay/app/.env`, затем перезапуск |

`update.sh` сам делает резервную копию перед обновлением и проверяет, что сервис поднялся.

## Резервные копии

Каждую ночь в 03:30 база и отчёты сохраняются в `/var/backups/fairplay` (хранятся 14 дней).
**Копия на том же сервере не спасёт при его потере** — настройте отправку на другой сервер: в
`/etc/cron.d/fairplay-backup` допишите перед `bash` переменную `BACKUP_REMOTE=user@host:/путь`
(нужен SSH-доступ по ключу), либо регулярно скачивайте копии к себе:
`scp root@IP:/var/backups/fairplay/*.tar.gz .`

Восстановление: остановить сервис, распаковать архив в `/home/fairplay/app/data/`
(файл `app.db` и папку `reports`), вернуть владельца `chown -R fairplay:fairplay /home/fairplay/app/data`, запустить.

## Перед запуском продаж

- [ ] Заполнить реквизиты продавца в админке и проверить страницы `/offer.html`, `/privacy.html`, `/consent.html`, `/contacts.html`
      (незаполненные места подсвечены жёлтым).
- [ ] **Согласовать тексты оферты, политики и согласия с юристом.** На сайте лежат шаблоны.
      При любом изменении текстов обновите дату `LEGAL_VERSION` в `lib/legal.js` — она сохраняется у каждого
      пользователя вместе с отметкой о согласии.
- [ ] Подать уведомление об обработке персональных данных в Роскомнадзор: https://pd.rkn.gov.ru
- [ ] Подключить ЮKassa (модерация сайта), включить отправку чеков (54-ФЗ) и выставить код НДС в админке.
- [ ] Настроить внешние резервные копии (см. выше).

## Что уже настроено для безопасности

- Сервис слушает только `127.0.0.1:3000`, снаружи открыты лишь порты 22, 80, 443 (ufw).
- HTTPS-сертификат Let's Encrypt выпускается и продлевается Caddy автоматически.
- Служба работает от отдельного пользователя без прав администратора и может писать только в `data/`.
- `.env` доступен только пользователю `fairplay` (права 600); ключ GitHub — только на чтение.
